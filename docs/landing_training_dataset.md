# 三阶段着舰视觉训练集设计

设计对象是一台刚性固定于机身的相机。参考位置均为**起落架轮底平面中心相对 H 中心**。轨迹目标使用水平航向系：船首方向 +X、左舷 +Y、重力反方向 +Z，不随甲板横摇/纵摇倾斜；真实甲板系仍随舰体旋转，独立用于成像、几何标签和 PnP。50 m 后方是相对 H 中心，而不是相对舰尾；正上方 5 m 在 NED 中是 `[0,0,-5]` m。海面、舰船、相机使用同一 ENU 世界系；保存原生飞机 NED 位置、体轴 knot 速度和弧度姿态，便于与 innerLoop 对齐。

## 阶段与采样

| 阶段 | 标称轨迹 | 时长与采样 | 训练目标 |
|---|---|---|---|
| approach | 轮底中心 [-50,0,50] → [0,0,5] m | 36–44 s，选 60 帧 | 小 H、舰船/海面背景、追近和下降 |
| window_hold | 水平航向系 [0,0,5] m，即 NED [0,0,-5] m 相对悬停 | 6–12 s，选 60 帧 | 甲板运动下稳定定位与等待窗口 |
| touchdown | [0,0,5] → [0,0,0] m | 12–18 s，选 60 帧 | 近距大 H、着舰前姿态/图像退化 |

每阶段速度首尾为零，前后各 12% 时间平滑加减速，中间 76% 时间保持标称恒定相对速度。阶段一平均追近约 1.1–1.4 m/s、下降约 1.0–1.25 m/s；中段速度略高于阶段平均速度。阶段二 nominal 相对静止，但保留较小跟踪残差；阶段三标称水平误差为零，在末端抑制残差使轮底中心最终与 H 中心重合。停止点是轮底中心，不是质心或相机光心。没有用轨迹伪造飞机/舰船动力学或触舰接触力。

全轨迹以 10 Hz 生成，图像按阶段均匀抽样，故各阶段选出的图像时间间隔不同。轨迹 JSON 保留所有时刻，可用于后续时序训练/回放，不应把抽样图像当作等间隔序列。曝光和滚动读出使用相邻的稠密轨迹时刻计算，而非相隔较远的已选图像。

窗口预测器由用户另行实现。默认仅随机采样等待时长，并将 window_source 标为 sampled_wait_not_predictor；不把它声称为真实窗口预测。配置 mission.window_events_file 时读取 `{sequence_id: wait_seconds}` JSON，值是进入阶段二后等待的秒数；缺少航次或时间非正时拒绝生成。触舰窗口的滚转/升沉条件不由本生成器猜测。每个航次包括三个阶段，阶段三首帧 window_open=true。

## 固定相机光学布局

原窄视场、直接随机相机位姿的生成器不用于这套数据。新生成器计算：

`T_world_camera = T_world_body @ T_body_camera`

每个航次内 T_body_camera 固定，不逐帧 look-at H，也不使用云台。不同航次允许小量固定安装误差。

当前是一组**待标定的设计值**，并非 UH-60 手册尺寸或实际硬件选型：

- OpenCV 相机 +X 右、+Y 下、+Z 前；机体 forward/right/down。
- 安装在**机腹前部中心线、机腹外表面下方的短支架上**。相机光心相对质心 [2,0,1.11] m，即前方 2 m、下方 1.11 m。
- 简化机身为半轴 [5.6,1.25,1.1] m 的椭球；安装点处机腹下表面约为 z=1.027 m，光心向外突出约 8.3 cm。原 [0,0,0.1] m 位于机体内部，现在会被安装检查拒绝。机身、主轮、尾轮与支柱均采用可替换几何近似，不能当作 UH-60 实测蒙皮位置。
- 光轴接近竖直向下，向机尾偏 6°（optical_down_deg=96）。相机在轮底中心前方，末端 H 会处于其后下方；宽视场同时覆盖进近时的前下方目标。不随阶段改变安装角。
- 轮底中心相对质心 [0,0,2.9] m。无姿态倾斜的触舰几何下，光心距离甲板约 1.79 m；考虑采样姿态和甲板摇摆后，默认轨迹中的最小甲板法向高度约 1.59 m。
- 水平/垂直视场为 140°/145°，分辨率 1280×960，按针孔模型推导独立 fx/fy。训练默认 512×512。
- H 外轮廓为 6×6 m。默认中距最小投影约 22.2 px，缩放到 512 后只有约 9 px，因此中距定位精度必须重点验证；可提高训练分辨率或后续增加正确映射的 ROI 策略。

宽视场与接触时相机高度共同覆盖 H。`plan.json` 按航次/阶段分别给出入画率、机身/起落架射线无遮挡率、同时满足二者的可见率和最小像素尺度。默认 60 航次中 H 中心可见率为 100%，approach/window_hold 四角可见率为 100%，touchdown 最差航次四角可见率约 99.3%。Blender RGB 和 mask 使用同一组机身/起落架几何，并随飞机刚性运动；遮挡区域不会标成可见 H。光心位于内部/表面时拒绝生成。不能把这些几何结果等同于已训练网络性能或真实 UH-60 可安装性；需用实测/CAD 外形检查附件、支架和镜头窗口。当前模型未包含完整机身、旋翼、天线及挂载物。

布局侧视示意见 `output/figure/landing_camera_mount.png`，更新后的五种天气预览见 `output/figure/landing_three_stage_preview.png`。相机挪至机腹正中虽然避免机身遮挡，但部分下降高度下主轮会挡住关键点，因此采用前移安装。

真实超广角镜头通常存在强畸变。当前数据是**假定标定并校正后的零畸变针孔图像**；需确认实际矫正后视场仍能达到设计值，而不是直接把厂家原始鱼眼 FOV 填进去。尚未模拟鱼眼镜头的原始成像、实际 MTF 或不等焦距校正损失。

## 直线航行、舰尾流与舰船晃动

舰船质心沿固定艏向以 10–16 knot 匀速航行，叠加横摇 0.5–3°、纵摇 0.3–2°和升沉 0.1–0.6 m，周期 6–11 s；艏向不做随机绕航。H 舰体偏移为待替换的 [-45,0,-5.5] m，随舰体旋转，不能直接把 H 当作舰船质心。

飞机机头跟随前进速度方向，不绕舰或向后飞；根据 CG 速度修正 yaw，保留 0.3°级偏航跟踪误差。侧滑角逐帧记录，可检查抑制情况。机体滚转/俯仰扰动会通过安装变换改变相机视角。

舰尾流空气扰动采用 OU 有色运动残差，位置标准差 0.18 m、姿态标准差 1.5°、相关时间 0.7 s，并按舰后距离/高度衰减。阶段二残差缩小到 25%，切换边界残差连续归零。还有小幅高频机体/相机振动。**这是用于图像分布覆盖的运动学代理，不是 CFD、载荷或真实控制器响应模型**；之后应允许使用动力学/预测系统导出的轨迹替换它。

Blender 另有随时间传播的海面正弦波和简化艉部水面尾迹。水面尾迹与影响直升机的空气尾流是不同模型；未声称两者具有流体耦合。渲染的大海平面随舰船平移重新居中，避免绝对航行导致离开有限海面。

## 天气和传感器退化

五种环境各占 20% 航次：clear、fog、glare、night、night_fog。每航次固定天气类别，并独立变化太阳能量、噪声和雾密度。所有 split 都包含五种天气。

- 晴天：天空/太阳、海面反光和舰船阴影。
- 雾：跟随局部场景的体积介质，产生距离相关衰减与散射。夜间雾另叠加甲板灯照明。
- 眩光：高能量低太阳角和亮反射，叠加来自图像亮区的 bloom 与镜头鬼影。属于参数化镜头代理，不是某实际镜头的校准 PSF。
- 夜间：关闭太阳，降低天空亮度，使用舰上甲板泛光灯和边缘灯，并加入低照度读出/光子噪声。
- 模糊：按相邻姿态投影运动与曝光时间生成方向性模糊。滚动快门使用甲板平面一阶单应性，对 RGB、mask 和关键点同时变换；非甲板背景不具有精确深度相关滚动失真。

渲染标签采用独立发光材料 pass，保留几何遮挡并屏蔽体积雾；它是中曝光几何真值，不是从 RGB 白色阈值取得。浓雾、夜间或眩光可能让真实像素无法辨认 H，即使几何真值仍在画面内。额外 image_quality 标记 H/周围背景对比度；keypoint_train_visibility 屏蔽明显不可辨认样本的关键点损失。该判断是启发式，不替代实际检测成功率；分割标签仍保留已知几何区域。

## 数据、划分与训练

默认 12 航次/天气，共 60 航次，每航次 180 图像，共 10,800 图像。按天气分层，以完整航次分配约 40/10/10 航次到 train/val/test，对应 7,200/1,800/1,800 图像。独立随机种子生成不同完整轨迹，不把同一轨迹的天气或相邻帧跨 split。正式研究仍建议增加具有未见海况/安装误差/太阳条件的独立挑战测试集与真实数据验证，随机划分本身并不等同于域外测试。

输出根目录默认为 data/landing：

- trajectories：每航次全轨迹、阶段、窗口来源、安装几何和相机内参。
- rendered / annotations：RGB、二值 mask、兼容 HDataset 的四个固定顺序外角像素标注，另含 stage、weather、轮底相对位置（水平航向系、NED、真实甲板系）、ENU/body 位姿、几何/光度有效性。
- calibration/design.json：待标定设计参数以及标称 K、T_body_camera；每航次轨迹保存实际安装误差后的 T_body_camera。innerLoop 的 convert 应填写对应实际安装的 T_body_camera，不能沿用旧光心位置或把标称矩阵用于带随机安装误差的回放。
- splits/{train,val,test}.json：实际生成 annotation 的路径。
- plan.json / dataset_report.json：航次划分、全轨迹视场报告和实际渲染阶段/天气统计。

当前网络依然输出分割和四个外角，PnP/E SKF 流水线不改。部分出画或不可辨认时不强制训练无效关键点；单相机、广角、天气设置不会保证持续可用的末端导航。训练先分开评估三个阶段，并按天气和 stage/weather 组合检查 IoU、关键点误差；evaluate.py 已加入该分组。部署验收还需要像素误差→PnP→轮底 NED 误差以及连续失效时长，不能仅看分割 IoU。

## 运行

```bash
source .venv/bin/activate
# 根据当前配置重绘安装侧视示意（不代表三维无遮挡保证）
python -m visual_modeling.sensors.render_camera_mount
# 只生成轨迹与视场报告，无需 Blender
bash shell/generate_landing_dataset.sh --plan-only
# 正式 Blender 数据（耗时，默认 10,800 图像及 mask）
bash shell/generate_landing_dataset.sh
# 完整、独立 split 的小型 CPU 流程测试，不当作真实天气数据
bash shell/generate_landing_dataset.sh --renderer cpu --sorties-per-weather 3 --frames-per-stage 3 --width 320 --output /tmp/landing_smoke
# 五种天气 × 三个阶段可视化，仅预览，不生成训练 split
bash shell/generate_landing_dataset.sh --preview --sorties-per-weather 3 --frames-per-stage 3 --width 640 --samples 4 --output /tmp/landing_preview
# 正式数据生成后训练/分组评估
python -m visual_training.train --config configs/landing_training.yaml
python -m visual_training.evaluate --checkpoint visual_training/checkpoints/landing/best.pt --root data/landing --image-size 512
python -m visual_training.export_model --checkpoint visual_training/checkpoints/landing/best.pt --output visual_training/checkpoints/landing/h_detector.onnx --image-size 512
```

CPU 模式只验证合同、采样、划分和训练调用；包含同一机身/起落架几何在甲板平面上的简化遮挡投影，不包含完整舰船几何、体积雾、灯光、海面三维反射。Blender 应用需兼容项目 Python 包的版本，也可使用锁定 bpy 4.2。输出目录可重复生成，split/report 仅引用本次选中的样本；切换配置后遗留的未引用图像不能自行随机并入训练。
